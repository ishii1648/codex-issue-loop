# ADR-0006: 当面の質問回答をAI経由のCLI操作に統一する

- Status: Accepted
- Date: 2026-09-07
- Decision owners: codex-issue-loop maintainers

## Context

Issue #320への「ok と回答して」という依頼に対し、AIがタイトルだけを確認して通常コメントを投稿し、完了と報告した。canonical requestは未回答のままで、後から `agent-loop answer` で保存してworkerの再開を確認する必要があった。

ユーザーにrequest IDや専用コマンドを覚えてもらう運用は認知負荷が高い。一方、supervisorが通常コメントを回答として扱う方式には、議論の誤認、前の質問への遅延回答を次の質問へ適用する危険、編集・削除による撤回の誤解がある。質問時に受理する回答形式を示せば誤認を減らせるが、未回答が1件でも、次の質問の公開後に届く前の質問への「ok」は本文と時刻だけでは識別できない。

## Decision

- 当面、質問への回答はユーザーがAIに自然文で依頼し、AIが対象requestを確認して既存CLIへ渡す経路を標準とする。GitHubコメント経由の回答は標準運用に採用しない。
- ruleはIssueの本文・質問コメントの確認とskillへの誘導を担う。skillはcanonical requestの照合、回答契約の確認、標準入力によるanswer実行、同じrequestの回答済み確認を担う。
- 既に示された回答は再質問しない。対象や回答が曖昧な場合だけ確認し、推奨選択肢を勝手に承認しない。ユーザーがコメント投稿だけを明示した場合はその範囲を守る。
- 回答保存とworker再開を区別する。回答後の待機・隔離を理由に二重回答や手動のstate・label変更を行わない。
- repositoryのAGENTS.mdから同梱skillを参照し、user-scope ruleは既存の `agent-loop init` で反映する。配布済みskillはバイナリ・manifestと整合性管理されるため単独上書きせず、配布物の更新は既存の検証済みRelease経路を使う。

## Consequences

ユーザーは「Issue #320 に ok と回答して」と依頼でき、request IDの転記が不要になる。回答保存・再開の既存境界を再利用でき、コメントを解釈する新たなruntime機構は不要である。

AIが実行ホストへ接続できなければ回答を保存できない。GitHubだけで回答を完結する利便性は得られず、AIにも質問とrequestを取り違える可能性が残るため、コメントのrequest IDとcanonical状態の照合を必須とする。

この決定はAIの運用経路を定めるもので、#320 / PR #324や旧PR #268の取消・マージ・配備を操作するものではない。それらのGitHub回答機能を標準運用へ導入する場合は、この決定を再検討する。

## Alternatives considered

- **専用コメントコマンド**: requestを明示できるが、ユーザーに構文とIDの転記を要求する。当面はAIがCLI引数を扱う。
- **通常コメントの自動受理**: 質問に選択肢や回答形式を示す方式は将来の候補とする。質問の公開境界、遅延回答、同時回答、同一アカウントでの自動投稿除外、編集・削除、再起動後の再取り込みを検証してから再判断する。
- **ruleだけで対処**: 誘導だけでは保存・検証手順が不足するため、skillと併用する。
